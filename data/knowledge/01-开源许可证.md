# 开源许可证速查

## 什么是开源许可证

开源许可证是版权持有人授予他人的法律许可，规定使用者可以如何使用、修改、分发软件。
没有许可证的公开代码默认保留所有权利，**不等于开源**。

## 常见许可证对比

| 许可证 | 类型 | 允许商用 | 修改后是否必须开源 | 是否需保留版权声明 |
| --- | --- | --- | --- | --- |
| MIT | 宽松 | 是 | 否 | 是 |
| Apache-2.0 | 宽松 | 是 | 否 | 是，且附专利授权 |
| BSD-3-Clause | 宽松 | 是 | 否 | 是，且不得用作者名义背书 |
| MPL-2.0 | 弱 copyleft | 是 | 仅修改的文件需开源 | 是 |
| LGPL-3.0 | 弱 copyleft | 是 | 动态链接可闭源 | 是 |
| GPL-3.0 | 强 copyleft | 是 | 是，衍生作品整体开源 | 是 |
| AGPL-3.0 | 强 copyleft | 是 | 是，网络服务也视为分发 | 是 |

## 关键概念

**Copyleft（著佐权）**：要求衍生作品以相同许可证发布，保证代码持续开放。GPL 属于强 copyleft，MPL 与 LGPL 属于弱 copyleft。

**专利授权条款**：Apache-2.0 与 GPL-3.0 包含明确的专利许可，降低专利诉讼风险；MIT 与 BSD 不涉及专利条款。

**许可证兼容性**：把 GPL 代码并入 MIT 项目会迫使整个项目遵循 GPL；反向则可行，因此混合许可证时需先画出依赖树。

## 如何选择许可证

1. 希望被尽可能广泛使用、包括闭源商业产品：选择 MIT 或 Apache-2.0。
2. 希望社区改进必须回馈：选择 GPL-3.0。
3. 库被闭源软件链接但自身修改需开源：选择 LGPL-3.0。
4. 提供网络服务也必须开源：选择 AGPL-3.0。

## 课程作业建议

学生项目通常选择 MIT，因为它最短、最容易理解，并且与绝大多数第三方依赖兼容。
在仓库根目录放置 `LICENSE` 文件，并在 `README` 中注明许可证名称，即可满足开源发布的基本要求。
