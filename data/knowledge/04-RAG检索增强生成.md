# RAG 检索增强生成

## 要解决的问题

大模型的知识停留在训练数据截止时间，且容易编造内容（幻觉）。检索增强生成（Retrieval-Augmented Generation）在回答前先从外部知识库检索相关片段，把片段放进提示词，让模型基于事实回答。

## 标准流程

1. **加载**：读取 Markdown、PDF、网页等原始资料。
2. **切块**：按语义边界把长文档切成 300 到 800 字左右的片段，保留少量重叠避免语义被截断。
3. **索引**：用 embedding 模型把片段转成向量并存入向量库，或建立关键词倒排索引。
4. **检索**：把用户问题同样向量化，按相似度取回 Top-K 片段。
5. **生成**：把片段作为参考资料与问题一起送入模型，并提示模型"仅依据资料回答"。
6. **溯源**：返回答案时附带来源文件名与片段编号，便于人工核对。

## 切块策略

过大的块会稀释语义并浪费上下文，过小的块会丢失上下文。
中文场景常见配置：块大小 500 字、重叠 80 字，分隔符优先级为段落 > 换行 > 句号 > 逗号。

## 检索方式对比

| 方式 | 优点 | 缺点 |
| --- | --- | --- |
| 关键词 / TF-IDF | 零依赖、可离线、可解释 | 无法理解同义改写 |
| 向量检索 | 语义匹配能力强 | 需要 embedding 模型与向量库 |
| 混合检索 | 兼顾精确词与语义 | 实现与调参更复杂 |

本项目默认使用中文分词加 TF-IDF 余弦相似度，保证离线可用；配置 API Key 后可切换向量检索。

## 提示词约束

系统提示词中明确：只使用参考资料回答、资料不足时直接说明、禁止编造、引用时标注来源编号。
这能显著降低幻觉率，也是评估 RAG 效果的第一道防线。

## 常见问题

- **检索不到**：检查切块是否过大、问题与文档用词差异是否过大、是否缺少同义词扩展。
- **答非所问**：检查 Top-K 是否过小，或提示词中的资料块是否被截断。
- **答案与资料矛盾**：降低 temperature，并在提示词中强调以资料为准。

## 评估指标

召回率（相关片段是否被检索到）、忠实度（答案是否忠于资料）、答案相关性、端到端人工评分。
小规模课程项目可以用一组固定问题加人工打分，形成回归测试集。
